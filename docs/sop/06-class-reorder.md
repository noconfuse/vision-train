# SOP-6 类别顺序调整与删除

> 修改 `dataset.yaml` 中的类别顺序 / 类别定义，并同步重写历史标签里的 `class_id`。

## 6.1 目标

- 改类别顺序为什么必须同时重写标签
- 删除类别会引发的副作用
- 跨数据集统一类别顺序的注意事项

## 6.2 前置条件

- 目标数据集已稳定，不再频繁改类别体系。
- 已确定目标类别顺序或要删除的类别。

## 6.3 业务动作

### 调整类别顺序

更新 `dataset.yaml` 的 `names` 顺序，并重写所有 `labels/*.txt` 中的 `class_id`，保持类别名与 ID 对应一致。只改 yaml 不重写标签会导致类别语义错位，因此这个动作始终是「改 yaml + 重写所有标签」的组合操作。

旧模型与新数据集的类别语义可能不再对应；多数据集联合训练前必须先统一类别顺序。

### 添加类别

在类别区输入类别名后追加到 `dataset.yaml` 的 `names` 末尾；分类数据集同时在 `train/` 与 `val/` 下创建空类别目录。添加类别不影响已有标签。

### 删除类别

从 `dataset.yaml` 移除类别，并删除所有 `labels/*.txt` 中对应行；标签因此变空的图片会一并删除（`delete_empty_files` 默认开启）。分类数据集下空类别目录同步清理，删除前要求二次确认。

## 6.4 为什么不能只改 `dataset.yaml`

YOLO 的类别语义绑定 `class_id`：只改 `dataset.yaml` 不重写标签，旧标签里的 `0 / 1 / 2` 仍保留原含义，标注器与训练都会语义错位。因此类别顺序调整始终是「改 `dataset.yaml` + 重写所有标签」的组合操作。

## 6.5 参数 / 字段含义

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `splits` | 参与重写的 split | 默认覆盖全部 `train / val / test` |
| `delete_empty_files` | 标签全空后删除图片 | 删除类别时默认开启，避免留下无标签图片 |

## 6.6 失败排查

| 现象 | 排查方向 |
| --- | --- |
| 改顺序后旧标注看着错位 | 必须通过系统的标签重排能力修改，参见 §6.3 |
| 删除类别后图片数变少 | 标签全空的图片被一并删除，是预期行为 |
| 多数据集联合训练类别语义不一致 | 训练前先统一类别顺序 |

# SOP-6 类别顺序调整与删除

> 修改 `dataset.yaml` 中的类别顺序 / 类别定义，并同步重写历史标签里的 `class_id`。

## 6.1 目标

让读者理解：

- 改类别顺序为什么必须同时重写标签
- 删除类别会引发的副作用
- 跨数据集统一类别顺序的注意事项

## 6.2 前置条件

- 目标数据集已稳定，不再频繁改类别体系。
- 已确定目标类别顺序或要删除的类别。

## 6.3 业务动作

### 调整类别顺序

更新 `dataset.yaml` 的 `names` 顺序，并重写所有 `labels/*.txt` 中的 `class_id`，保持类别名与 ID 对应关系一致。**只改 `dataset.yaml` 不重写标签，会导致类别语义错位，标注器与训练都会受影响**，因此这个动作始终是"改 yaml + 重写所有标签"的组合操作。

需要警惕的是：旧模型与新数据集的类别语义可能不再完全对应；多数据集联合训练前必须先统一类别顺序。

### 添加类别

从数据集预览顶部的类别筛选芯片区点击 "+" 输入类别名（Enter 或 ✓ 确认），类别会追加到 `dataset.yaml` 的 `names` 末尾。对于分类数据集，还会在 `train/` 与 `val/` 下创建对应的空类别目录。添加类别不影响已有标签。

### 删除类别

从 `dataset.yaml` 中移除该类别，并把所有 `labels/*.txt` 中对应行一并删除。删除入口有两处：

- **数据集预览芯片区**：在类别筛选芯片上悬浮后点击 × 按钮，二次确认后执行。
- **高级操作菜单**：进入"调整类别顺序"界面后，与重排共用一个列表，支持批量删除。

被删除类别原本对应的图片会变成无标签图片，**保留还是顺带删除这类图片由调用方决定**。分类数据集下，空类别目录也会一并清理。

### 标签整理（合并 / 校验）

合并近似类别或校验标签与 `dataset.yaml` 的一致性时使用，与"调整类别顺序"共用一套写盘路径，但触发场景不同。建议先做调整再做合并。

## 6.4 为什么不能只改 `dataset.yaml`

YOLO 的类别语义绑定 `class_id`：

- 旧标签中的 `0 / 1 / 2` 会继续保留原含义。
- 只改 `dataset.yaml` 不重写标签，会导致类别语义错位，标注器与训练都会受影响。
- 因此"改类别顺序"始终是"改 `dataset.yaml` + 重写所有标签"的组合操作。

## 6.5 参数 / 字段含义

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `splits` | 参与重写的 split | 默认覆盖全部 `train / val / test` |
| `delete_empty_files` | 删除标签全空后的图片 | 与"删除类别"配套，避免留下无标签图片 |

## 6.6 失败排查

| 现象 | 排查方向 |
| --- | --- |
| 改顺序后旧标注看着错位 | 必须通过系统工具改，参见 §6.3 |
| 删除类别后图像数与之前不同 | 删除类别会留下无标签图片是预期行为 |
| 多数据集联合训练类别语义不一致 | 训练前先统一类别顺序 |

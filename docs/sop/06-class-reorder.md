# SOP-6 类别顺序调整

> 修改 `dataset.yaml` 中的类别顺序，并同步重写历史标签里的 `class_id`。

## 6.1 什么时候需要做

当你发现：

- 类别顺序定义得不合理
- 想统一不同数据集之间的类别顺序
- 历史数据已经按旧顺序标注，但准备进入正式训练

这时不要手工逐个改标签，应使用系统提供的顺序调整工具。

## 6.2 为什么不能只改 `dataset.yaml`

YOLO 的类别语义依赖 `class_id`。

如果你只改 `dataset.yaml`，但不重写历史标签文件，那么：

- 旧标签中的 `0`、`1`、`2` 会继续保留原含义
- 训练时类别语义就会错位
- 标注器里看到的类别也会变得混乱

所以“改类别顺序”一定是两步同时完成：

1. 改类别定义顺序
2. 重写所有标签文件中的 `class_id`

## 6.3 系统会帮你做什么

通过系统工具调整后，后端会自动：

- 更新 `dataset.yaml`
- 重写所选 split 中的标签文件
- 保持类别名与 `class_id` 对应关系一致

这比手工修改更安全，也更适合已有数据量较大的情况。

## 6.4 操作建议

在开始前建议先确认：

- 当前数据集已经稳定，不再频繁改类别体系
- 你知道目标顺序应该是什么
- 最好先备份一份数据集

完成调整后，建议立即抽样检查几张图，确认类别显示正常。

## 6.5 删除整个类别意味着什么

系统也支持删除某个类别，但这是强破坏性操作。

删除后会发生：

- `dataset.yaml` 中移除该类别
- 对应标签行会从所有标签文件中删除
- 如果一张图删完后没有任何标签，图片仍然保留，只是变成无标签图片

> 如果你只是想降低某类在训练中的影响，优先考虑 [SOP-5 弱类补偿采样](05-class-rebalance.md) 或重新整理数据，而不是直接删除类别。

## 6.6 注意事项

- 这类操作会直接改动真实数据，不可当作普通筛选来用
- 调整顺序后，旧模型与新数据集的类别语义可能不再完全对应
- 如果多个数据集要联合训练，最好先统一它们的类别顺序

## 6.7 完成后如何验证

建议至少做这几步：

1. 重新打开数据集详情页，确认类别顺序已更新
2. 随机打开几张图，检查框的类别是否正确
3. 如果后续要训练，再重新检查一次训练配置里的类别上下文

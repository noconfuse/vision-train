# SOP-4 自动标注

> 用已有模型批量生成标注草稿，再回到数据集详情页逐张复核。

## 4.1 自动标注的定位

自动标注的目的不是替代人工，而是先帮你生成一批“待复核”草稿，降低纯手工标注成本。

适合的场景：

- 已经有一版可用模型
- 当前数据集还有大量未标注图片
- 想先批量补草稿，再集中复核

## 4.2 开始前建议

建议先确认：

- 当前项目里已经有可用模型
- 数据集类别和模型输出类别大体一致
- 你知道本次要处理哪个 split

如果模型来源和当前业务差异很大，自动标注的误检和漏检会明显增多。

## 4.3 可以使用哪些模型

当前通常会有两类候选模型：

- 当前项目历史训练得到的模型
- 系统中的预训练模型

优先建议：

- 同项目、同场景的历史模型
- 其次才是通用预训练模型

## 4.4 自动标注结果会写到哪里

自动标注不会直接覆盖人工标签，而是先写成“待复核草稿”。

你可以把它理解成两层：

- 正式标签：人工确认后的结果
- 自动标注草稿：等待复核的结果

典型路径：

```text
projects/<project>/training/<dataset_name>/auto_labels/<split>/
```

而正式标签仍然在：

```text
projects/<project>/training/<dataset_name>/<split>/labels/
```

## 4.5 当前版本如何使用

典型流程如下：

1. 打开目标数据集详情页
2. 触发“自动标注”
3. 选择要处理的 split、模型和阈值
4. 启动任务
5. 等待任务完成
6. 在数据集详情页用“待复核”筛选回看结果
7. 打开图片逐张确认并保存

## 4.6 任务完成后你会看到什么

自动标注完成后，系统通常会给出类似下面的信息：

- 新增了多少个标注框
- 多少张图片进入了“待复核”

此时这些图片不会自动变成最终标注，需要你继续人工确认。

## 4.7 复核时重点看什么

建议优先检查：

- 是否有误检框
- 框位置是否偏移
- 类别是否正确
- 是否存在漏检目标

处理完成后及时保存，这样草稿才能并入正式标签。

## 4.8 使用建议

- 先在一小批图片上试跑，确认模型适配度
- 误检多时，适当提高置信度
- 漏检多时，适当降低置信度
- 不要把自动标注结果直接当最终标签交付

## 4.9 常见问题

- **跑完后几乎没有框？** 可能是模型不适合这批数据，或阈值设得太高。
- **结果很多但质量差？** 说明模型和当前场景不匹配，建议先补标一批重新训练。
- **会不会覆盖掉我原来的人工标签？** 不会，当前版本默认先写入待复核草稿。
- **想把草稿全部清掉怎么办？** 可以回到数据集详情页使用“清除待复核标注”。

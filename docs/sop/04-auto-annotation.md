# SOP-4 自动标注

> 用已有模型为数据集生成"待复核草稿"，再回到 SOP-3 完成人工确认。

## 4.1 目标

让读者理解：

- 自动标注在业务闭环里的位置
- "待复核草稿"与"正式标签"的边界
- 自动标注的输入 / 输出与失败排查

## 4.2 前置条件

- 目标数据集已导入并有图片，参见 [SOP-3 数据标注](03-annotation.md)。
- 当前项目内或预训练模型目录中存在可用模型：
  - 同项目历史训练得到的模型（推荐）。
  - 系统中的预训练模型。

## 4.3 业务动作

### 发起自动标注

针对一个数据集 + 一个 split 发起一次自动标注任务，产出待复核草稿，写入 `projects/<project>/training/<dataset_name>/auto_labels/<split>/`。**正式标签始终位于 `<split>/labels/`，不会被覆盖**，所以草稿出错可以放心重跑。

### 任务完成后的复核

回到 [SOP-3 数据标注](03-annotation.md) 的"自动标注草稿复核"流程，逐张核对：删除误检、调整框、补充漏标，保存即并入正式标签。

### 清除待复核草稿

希望丢弃当前所有自动标注草稿时使用，**只清空 `auto_labels/<split>/`，不动正式标签**。

## 4.4 模型来源优先级

| 来源 | 推荐度 | 说明 |
| --- | --- | --- |
| 同项目历史模型 | 高 | 与场景一致，误检与漏检少 |
| 同任务类型预训练模型 | 中 | 通用预训练，适合作为兜底 |
| 跨任务类型模型 | 低 | 不推荐，容易出现大量误检 |

## 4.5 参数 / 字段含义

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `split` | 要处理的 split | `train` / `val` / `test` |
| `model` | 模型来源 | 历史训练产物或预训练模型 |
| `confidence` | 置信度阈值 | 提高阈值降低误检，但漏检会增加 |
| `iou` | NMS IOU 阈值 | 影响重叠框的取舍 |

## 4.6 任务状态与失败排查

### 状态

| 状态 | 语义 |
| --- | --- |
| `pending` | 等待调度 |
| `running` | 正在推理 |
| `completed` | 草稿已生成，可复核 |
| `failed` | 推理失败，附带错误信息 |
| `cancelled` | 被取消 |

### 失败排查

| 现象 | 排查方向 |
| --- | --- |
| 草稿几乎为空 | 模型与场景不匹配 / 阈值过高 |
| 草稿很多但质量差 | 模型与场景不匹配，建议先人工补标一批重新训练 |
| 找不到草稿 | 确认 `auto_labels/<split>/` 是否被清空或被外部删除 |
| 自动标注覆盖了正式标签 | 不应发生；本能力只写 `auto_labels/`，如出现需检查实现 |

# SOP-4 自动标注

> 用已有模型为数据集生成标注草稿，再由人工复核和确认。

## 4.1 目标

自动标注适合这些场景：

- 已经完成了第一轮小样本标注
- 已经训练出一版可用模型
- 还有大量图片需要补标或复核

它的定位不是“替代人工”，而是“先给草稿，再由人工确认”。

## 4.2 开始前

建议先确认：

- 当前项目里已有可用模型
- 目标数据集中的图片已经整理完成
- 你准备处理的 `train / val / test` 范围已经明确

如果模型和当前数据集类别差异太大，自动标注结果可能会很差，这时更适合先人工补一小批，再重新训练一版模型。

## 4.3 模型怎么选

自动标注可以使用两类模型：

- 项目里历史训练得到的模型
- 系统已有的预训练模型

一般建议优先使用**同一项目、同一业务场景**下训练出来的模型，这样结果更接近你的标签标准。

## 4.4 自动标注会怎么写入

自动标注生成的是**待确认草稿**，不会直接把人工标签静默覆盖掉。

你可以把它理解成两层结果：

- **正式标签**：已经人工确认过的标签
- **自动标注草稿**：模型新生成、等待复核的标签

后续在标注页面打开图片时，可以同时看到人工标签和自动标注草稿；只有你保存或确认后，草稿才会并入正式标签。

## 4.5 如何使用

### 选择处理范围

通常需要确认以下内容：

| 项目 | 说明 |
| --- | --- |
| 数据集 | 这次要处理哪个数据集 |
| split | 要处理 `train`、`val` 还是 `test` |
| 模型 | 本次自动标注使用哪个模型 |
| 置信度 | 越高越保守，越低越容易出更多框 |

### 启动任务

启动后，任务会进入任务中心。你可以在任务中心查看：

- 任务状态
- 处理进度
- 错误信息

### 复核结果

任务完成后，建议不要直接把自动标注当成最终结果，而是进行人工复核：

- 删除误检框
- 调整位置不准的框
- 补充漏检目标
- 确认类别是否正确

这样处理完的数据，才更适合进入训练。

## 4.6 文件会写到哪里

### 自动标注草稿

```text
projects/<project>/training/<dataset_name>/auto_labels/<split>/
```

### 人工确认后的正式标签

```text
projects/<project>/training/<dataset_name>/<split>/labels/
```

## 4.7 使用建议

- 先在一小批图片上验证效果，再放大到整个数据集
- 如果误检很多，先提高置信度再试
- 如果漏检很多，先降低置信度再试
- 若模型来自其他项目或其他类别体系，先小范围试跑，不要直接全量使用

## 4.8 常见问题

| 现象 | 处理建议 |
| --- | --- |
| 跑完了但几乎没有框 | 当前模型不适合这批数据，或置信度设置过高 |
| 结果很多但质量差 | 模型和数据集场景不匹配，建议先人工补标一批再训练 |
| 担心覆盖已有人工标签 | 自动标注默认先生成草稿，复核确认后才并入正式标签 |
| 任务进度长时间不动 | 先看任务中心里的错误信息，再检查模型是否可用、图片是否过大 |

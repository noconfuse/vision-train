# SOP-4 自动标注

> 用已有模型为数据集生成待复核候选，再回到 SOP-3 在标注弹窗中审核确认。

## 4.1 目标

- 自动标注在业务闭环里的位置
- 待复核候选与正式标签的边界
- 自动标注的输入 / 输出与失败排查

## 4.2 前置条件

- 目标数据集已导入并有图片，参见 [SOP-3 数据标注](03-annotation.md)。
- 存在可用模型：同项目历史训练模型（推荐）或预训练模型。
- 模型类别与数据集类别通过对齐校验；类别不一致时任务拒绝执行，避免把未知类别写进标签。

## 4.3 业务动作

### 发起自动标注

对一个数据集 + 一个 split 发起推理任务，候选写入 `projects/<project>/training/<dataset_name>/auto_labels/<split>/`，逐框附带置信度与出处 meta。**正式标签始终位于 `<split>/labels/`，不会被覆盖**，候选出错可直接重跑或清空。

### 相似探测（以框找框）

以选中框为样本，在当前 split 检索外观接近的区域，命中结果同样作为候选写入待复核，不动人工标签。

### 候选审核

回到 [SOP-3 数据标注](03-annotation.md) 的待复核审核流程，逐张核对：删除误检、调整框、补充漏标，保存即并入正式标签。

### 清空待复核候选

丢弃筛选范围内图片的候选，**只动 `auto_labels/<split>/`，不影响正式标签**。

## 4.4 模型来源优先级

| 来源 | 推荐度 | 说明 |
| --- | --- | --- |
| 同项目历史模型 | 高 | 与场景一致，误检漏检少 |
| 同任务类型预训练模型 | 中 | 通用预训练，作为兜底 |
| 跨任务类型模型 | 低 | 不推荐，误检多 |

## 4.5 参数 / 字段含义

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `split` | 要处理的 split | `train` / `val` / `test` |
| `model` | 模型来源 | 历史训练产物或预训练模型 |
| `confidence` | 置信度阈值 | 提高阈值降低误检，漏检增加 |
| `iou` | NMS IOU 阈值 | 影响重叠框取舍 |

## 4.6 任务状态与失败排查

### 状态

`pending`、`running`、`completed`（候选可复核）、`failed`（附错误信息）、`stopped`（被主动停止）。

### 失败排查

| 现象 | 排查方向 |
| --- | --- |
| 候选几乎为空 | 模型与场景不匹配 / 阈值过高 |
| 候选多但质量差 | 先人工补标一批重新训练 |
| 找不到候选 | 确认 `auto_labels/<split>/` 是否被清空或外部删除 |
| 任务因类别对齐失败 | 模型类别与数据集类别不一致，先对齐类别再重跑 |
| 正式标签被覆盖 | 不应发生；本能力只写 `auto_labels/`，出现即实现缺陷 |

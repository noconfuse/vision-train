# SOP-5 弱类补偿采样

> 在不破坏原数据集的前提下，生成一个针对弱类的补强数据集。

## 5.1 目标

让读者理解：

- 弱类补偿与"直接修改原数据集"的区别
- 多类目标倍数的语义
- 评估集保留策略与适用场景

## 5.2 前置条件

- 已存在目标数据集并完成基本标注，参见 [SOP-3 数据标注](03-annotation.md)。
- 知道哪些类需要补强，以及期望的目标倍数。

## 5.3 业务动作

### 发起补强

针对已有数据集发起一次弱类补偿采样，结果会作为一个新数据集落在 `projects/<project>/training/<new_dataset_name>/` 下。**源数据集保持不变**，补强是新建数据集。

### 预估（dry-run）

在不落盘的情况下拿到补强的预期结果：目标类数量、train 增量、val / test 在不同策略下的分布，方便先估算再生成。

### 正式生成

写入 `dataset.yaml` 与标准 YOLO 目录结构，按目标倍数复制 + 增强目标类样本，按策略保留或重新组织 `val / test`，并自动建立首个版本（走任务中心异步入库）。

## 5.4 参数 / 字段含义

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `new_dataset_name` | 新数据集名 | 必须不与现有数据集冲突 |
| `target_class_configs` | 每个目标类的目标倍数 | 每个类独立配置，不再要求统一倍数 |
| `non_target_keep_ratio` | 非目标类保留比例 | `0.3 ~ 0.6` 通常较稳妥 |
| `split` | 抽源数据的 split | 通常取 `train` |
| `copy_eval_splits` | 是否复制 `val / test` | 详见 §5.5 |
| `rebalance_eval_splits` | 是否重新整理 `val / test` | 与 `copy_eval_splits` 配合 |
| `enable_hflip` / `enable_vflip` | 是否启用对应翻转 | 取决于业务语义 |
| `color_jitter` | 颜色抖动强度 | `0.0 ~ 0.8` |
| `seed` | 复现种子 | 同种子下结果稳定 |

## 5.5 val / test 处理策略

| 模式 | 语义 | 适用 |
| --- | --- | --- |
| 保留原 `val / test` | 直接沿用源数据集的评估集 | 评估稳定性优先 |
| 重新整理 `val / test` | 按当前补强策略重新组织评估集 | 想让评估分布贴近补强后的训练分布 |

## 5.6 失败排查

| 现象 | 排查方向 |
| --- | --- |
| 预估无变化 | 源数据集该类样本极少 / 过滤条件不符合预期 |
| 生成后图片明显变多 | 目标类被复制 + 增强，是预期行为 |
| 评估指标波动大 | 检查 `val / test` 策略与训练集分布是否一致 |
| 与原数据集混淆 | 补强是新建数据集，与源数据集相互独立 |

# SOP-5 弱类补偿采样

> 针对类别分布不均的数据集，生成一个新的补强数据集，提高弱类样本占比。

## 5.1 什么时候用

如果你的数据集存在明显的长尾分布，例如：

- 正常样本特别多，异常样本特别少
- 某几个关键类别在训练集中占比很低
- 模型总是漏检少数类

这时可以通过“弱类补偿采样”生成一份新的训练数据集，而不是直接改坏原始数据集。

## 5.2 当前版本的能力重点

当前版本已经不是“给所有目标类统一一个倍数”的旧模式，而是：

- 可以同时选择多个目标类
- 每个目标类可以单独配置自己的目标倍数
- 可以控制非目标类保留比例
- 可以选择如何处理 `val / test`
- 可以先做预估，再真正生成数据集

## 5.3 会生成什么

弱类补偿不会直接修改原数据集，而是生成一个新的数据集目录。

典型结果：

```text
projects/<project>/training/<new_dataset_name>/
├── dataset.yaml
├── train/
├── val/
└── test/
```

生成完成后，新数据集会自动出现在数据集列表里。

## 5.4 典型使用流程

1. 进入目标数据集详情页
2. 点击“弱类补偿采样”
3. 填写新数据集名称
4. 选择一个或多个目标类
5. 为每个目标类分别设置目标倍数
6. 设置非目标类保留比例
7. 选择 `val / test` 的处理方式
8. 先做预估
9. 确认结果合理后再正式生成

## 5.5 关键参数怎么理解

### 新数据集名称

补强结果会生成一份全新的数据集，建议名称能看出来源和用途。

### 目标类配置

当前版本使用“按类分别配置”的方式：

- 类别 A 可以补到 8 倍
- 类别 B 可以补到 4 倍
- 不再要求所有目标类共用同一个倍数

这更适合真实业务里的不平衡情况。

### 非目标类保留比例

这个值决定多数类保留多少。

- 值越低，多数类压缩越明显
- 值越高，越接近保留原始分布

如果你不确定，从 `0.3 ~ 0.6` 开始通常比较稳妥。

### 增强方式

当前常见增强项：

- 水平翻转
- 垂直翻转
- 颜色抖动

是否启用要看你的业务语义是否允许。

### `val / test` 处理方式

当前界面是用户向表达，不再用旧的“是否复制 / 是否平衡 eval”口径，而是两种模式：

| 模式 | 含义 |
| --- | --- |
| 保留原 `val / test` | 直接沿用原评估集，更稳 |
| 重新整理 `val / test` | 按当前补强策略重新组织评估集 |

如果你更看重评估稳定性，优先建议保留原 `val / test`。

## 5.6 为什么建议先预估

预估可以先告诉你：

- 生成后各类别大概会变成什么规模
- `train` 集会增加多少图片
- `val / test` 在不同处理方式下的大致结果

这样你可以先判断结果是否过激，再决定要不要真正落盘。

## 5.7 使用建议

- 只补最影响训练效果的弱类，不要一次把所有类都做重采样
- 先保守试一版，不要一开始就把倍数拉得很高
- 如果源数据本身标注不完整，先补标再做补强
- 生成新数据集后，建议单独训练对比，不要直接覆盖原训练结论

## 5.8 常见问题

- **为什么要生成新数据集，而不是直接改原数据集？** 因为补强是实验性整理，保留原始数据集更安全。
- **目标类选了但预估没变化？** 可能该类别在源数据集中样本极少，或过滤条件不符合预期。
- **为什么生成后图片明显变多？** 因为目标类会复制增强，这是预期行为。
- **`val / test` 应该选哪种模式？** 大多数情况下优先“保留原 `val / test`”，这样评估更稳定。

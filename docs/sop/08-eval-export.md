# SOP-8 评估与导出

> 对训练结果做质量检查，并把模型导出成可用于外部部署或集成的文件。

## 8.1 目标

训练完成后，通常会做两件事：

- **评估**：判断这次训练结果是否够好
- **导出**：把模型转换成目标环境可使用的格式

这一步适合在你已经得到至少一版可用训练结果之后进行。

## 8.2 评估适合什么时候做

建议在这些场景下做评估：

- 想比较两次训练谁更好
- 想确认当前模型是否可以进入部署或试用
- 想判断继续加数据、改参数是否还有必要

## 8.3 如何查看评估结果

评估是基于某一次训练结果发起的。启动后，你可以在任务中心或训练历史里查看：

- 当前任务状态
- 评估是否成功完成
- 核心指标结果
- 相关可视化图表

你不需要记住后台流程，只需要把评估理解成“对这次训练结果做一次质量检查”。

## 8.4 重点看哪些指标

常见指标可以这样理解：

| 指标 | 关注点 |
| --- | --- |
| Precision | 预测为目标时，有多少是真的 |
| Recall | 实际目标中，有多少被找出来 |
| mAP50 | 在较宽松标准下的整体检测效果 |
| mAP50-95 | 在更严格标准下的整体检测效果 |

如果你的业务更怕漏检，就更关注 Recall；
如果你的业务更怕误报，就更关注 Precision。

## 8.5 如何导出模型

导出同样是基于某一次训练结果发起的。当前常见导出项包括：

| 项目 | 说明 |
| --- | --- |
| 导出格式 | 例如 ONNX、OpenVINO、TensorRT |
| 图片尺寸 | 导出时使用的输入尺寸 |
| 半精度 FP16 | 减少模型体积或提升部分设备上的推理效率 |
| INT8 量化 | 进一步压缩模型并提升部分设备上的推理效率 |

如果你暂时不确定目标部署环境，通常可以先导出一份 ONNX 作为通用结果。

## 8.6 导出结果会写到哪里

每次导出都会生成独立目录：

```text
projects/<project>/training_outputs/<dataset_name>/<run_id>/export/<export_task_id>/
```

你可以把它理解成“同一次训练结果下的某一次导出记录”。

## 8.7 如何选择导出格式

### ONNX

适合想保留较强通用性的场景，便于后续接入不同推理框架。

### OpenVINO

适合后续运行环境偏向 Intel 设备的场景。

### TensorRT

适合后续运行环境已经明确使用 NVIDIA GPU 的场景。

如果你的部署环境还没定，先导出 ONNX 更稳妥。

## 8.8 关于 INT8 量化

INT8 量化通常能进一步减小模型体积、提升部分设备上的推理效率，但并不是所有场景都适合直接使用。

建议这样处理：

- 先保留一份普通导出结果
- 再额外导出一份 INT8 结果
- 用你自己的业务样本做一次实际推理对比

如果量化后精度下降明显，就优先使用非 INT8 版本。

## 8.9 常见问题

| 现象 | 处理建议 |
| --- | --- |
| 评估成功但结果不理想 | 回看数据质量、类别分布和训练参数，再决定是否继续迭代 |
| 导出失败 | 先确认训练结果完整，再检查当前环境是否支持目标导出格式 |
| 不知道该导出哪种格式 | 先导出 ONNX，再根据目标部署环境补导其他格式 |
| INT8 导出后效果变差 | 先用普通版本验证，INT8 作为性能优化项单独评估 |

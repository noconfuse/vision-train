# SOP-8 评估与导出

> 在训练工作流里继续完成测试评估，并导出可部署的模型文件。

## 8.1 当前版本里的位置

评估和导出都不是独立页面，而是训练工作流中的后续步骤：

- 训练配置
- 任务详情
- 测试评估
- 模型导出

也就是说，先有训练工作流，后面才谈评估和导出。

## 8.2 发起评估前先确认一件事

当前版本发起“测试评估”有一个重要前提：

- 数据集需要有 `test` split

如果没有测试集，评估入口会受限。这时应先回到数据集页补齐或重整 `test` 集。

## 8.3 什么时候做测试评估

建议在这些场景下发起：

- 想比较不同训练结果谁更好
- 想判断当前模型能否进入部署验证
- 想看是否还需要继续补数据或调参数

## 8.4 评估结果怎么看

评估完成后，通常重点关注这些指标：

| 指标 | 含义 |
| --- | --- |
| Precision | 预测出的框里，有多少是真的 |
| Recall | 实际目标里，有多少被找出来 |
| mAP50 | 较宽松标准下的整体效果 |
| mAP50-95 | 更严格标准下的整体效果 |

经验上：

- 更怕漏检时，更关注 Recall
- 更怕误报时，更关注 Precision
- 想看整体上线可用性时，重点看 mAP 指标

## 8.5 当前版本怎么发起导出

导出同样挂在当前工作流下，常见可选项包括：

| 参数 | 说明 |
| --- | --- |
| 导出格式 | ONNX、OpenVINO、TensorRT |
| 图片尺寸 | 导出模型的输入尺寸 |
| 半精度 FP16 | 减小体积、提升部分环境推理效率 |
| INT8 量化 | 进一步压缩模型，但可能带来精度损失 |

需要注意：

- `FP16` 和 `INT8` 当前不能同时开启
- `TensorRT` 依赖主机运行环境支持，不是所有机器都能导出

## 8.6 导出格式怎么选

### ONNX

如果你还没确定最终部署环境，优先导出 ONNX 最稳妥。

### OpenVINO

适合后续运行环境偏向 Intel 设备时使用。

### TensorRT

适合已经明确会部署在 NVIDIA GPU 环境中。

## 8.7 导出记录有什么用

当前导出页不只是一个“开始导出”按钮，还会维护导出记录列表。

你可以在这里看到：

- 当前导出任务状态
- 进度
- 产物路径
- 文件大小
- 下载入口
- 删除记录入口

这意味着同一个训练工作流下可以保留多次导出尝试，而不是只保留最后一次结果。

## 8.8 导出结果通常在哪里

典型目录如下：

```text
projects/<project>/training_outputs/<dataset_name>/<run_id>/export/<export_task_id>/
```

不同格式下，最终下载物可能是：

- 主模型文件
- OpenVINO 整包
- 其他相关导出产物

## 8.9 使用建议

- 先做一次测试评估，再决定是否导出
- 第一次导出时，优先保留一份常规版本
- 如果要尝试 INT8，建议额外导出一份，不要直接替代普通版本
- 导出后最好用真实业务样本做一次推理验证

## 8.10 常见问题

- **为什么不能开始测试评估？** 先检查当前数据集是否存在 `test` 集。
- **为什么 TensorRT 是灰的？** 说明当前主机环境不支持 TensorRT 导出。
- **导出该选哪种格式？** 没有明确部署环境时，优先 ONNX。
- **INT8 导出后效果变差怎么办？** 保留普通版本，把 INT8 作为单独性能优化尝试。

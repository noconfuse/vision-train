# SOP-7 模型训练

> 在训练页以“工作流”方式管理训练配置、训练详情、测试评估和模型导出。

## 7.1 先理解当前训练页

当前版本的训练页已经不是“启动一次训练就结束”的旧模式，而是以**工作流**为中心：

- 左侧主区域：训练配置、任务详情、测试评估、模型导出
- 右侧信息列：当前工作流、已归档工作流、数据集概览

也就是说，你进入训练页后，首先是在管理一条工作流，而不是只管理一个临时训练任务。

## 7.2 什么情况下可以开始训练

建议先确认：

- 数据集结构完整
- 关键类别的标签质量基本可用
- 已经选好基线模型
- 当前设备资源足以支撑这次训练

如果数据还很乱，建议先回到 [SOP-3 数据标注](03-annotation.md) 做清洗。

## 7.3 进入训练页后怎么做

典型流程如下：

1. 从数据集列表点击“训练”
2. 进入训练页
3. 在右侧选择已有工作流，或点击“新建工作流”
4. 在“训练配置”步骤中选择模型与参数
5. 按需先做批次校准
6. 启动训练
7. 训练启动后切到“任务详情”查看进度
8. 训练完成后继续进入“测试评估”和“模型导出”

## 7.4 模型怎么选

当前常见来源有两类：

- 预训练模型
- 当前项目历史训练产生的模型

建议：

- 第一次训练一个数据集时，先用预训练模型起步
- 如果是同项目持续迭代，优先从历史结果继续训练

## 7.5 训练配置里重点看什么

最常见的参数包括：

| 参数 | 作用 |
| --- | --- |
| 训练轮数 | 决定这次训练的上限 |
| 批次 | 决定每次送入多少图片 |
| 图像尺寸 | 决定训练输入分辨率 |
| 学习率 | 决定收敛速度与稳定性 |
| 冻结层数 | 常用于迁移学习 |

如果你只是要跑第一版基线，建议先用保守参数把流程跑通，不要一开始就把增强和轮数开得很激进。

## 7.6 环境与批次校准怎么理解

训练页当前有单独的“环境与校准”信息区，会展示：

- 当前设备
- CPU / 内存 / GPU 信息
- 最近一次批次校准结果

批次校准适合这些情况：

- 第一次在这台机器上训练
- 换了模型
- 改了图片尺寸
- 不确定当前环境能承受多大批次

> 校准结果只是参考，不会自动帮你改写训练配置。

## 7.7 训练启动后看哪里

启动训练后，建议重点关注“任务详情”步骤。

这里通常会看到：

- 当前状态
- 任务进度
- 日志摘要
- 当前训练记录
- 是否支持继续训练

如果离开训练页，也可以去“任务中心”继续查看同一个任务。

## 7.8 当前版本的工作流记录

训练页右侧会维护两类记录：

- 当前工作流
- 已归档工作流

这样做的好处是：

- 你可以把同一个数据集的多轮尝试分开管理
- 不再把评估、导出和训练记录混成一团
- 历史工作流可以归档，不干扰当前迭代

## 7.9 停止训练与继续训练

### 停止训练

如果发现参数不合适，或者机器需要释放资源，可以停止当前训练任务。

### 继续训练

如果某次训练已经产生了可用权重，通常可以从对应工作流继续训练，而不是完全重来。

适合的场景：

- 上一轮主动停止
- 想在现有基础上继续增加轮数
- 想基于已有结果继续微调

## 7.10 训练产物在哪里

典型产物目录如下：

```text
projects/<project>/training_outputs/<dataset_name>/<run_id>/
```

常见内容包括：

- 配置快照
- 指标结果
- `best.pt`
- `last.pt`
- 曲线图与可视化图片

## 7.11 常见问题

- **进入训练页后为什么先让我选工作流？** 因为当前版本按工作流组织训练、评估和导出，不再是单任务模式。
- **训练一启动就失败？** 优先检查数据集结构、模型可用性和参数范围。
- **显存或内存不足？** 先减小批次，再考虑降低图片尺寸。
- **训练很慢怎么办？** 先用更小的图片尺寸和更保守的训练规模验证流程。
- **历史训练太多很乱？** 可以把旧工作流归档，只保留当前关注的记录。

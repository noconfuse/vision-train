# SOP-7 模型训练

> 在项目内以工作流为中心管理训练：训练配置、任务详情、测试评估、模型导出、部署模板生成，以及工作流归档与恢复。

## 7.1 目标

让读者理解：

- 训练工作流的语义边界与生命周期
- 训练配置 / 任务详情 / 测试评估 / 模型导出 / 部署模板 五个步骤的关系
- 工作流归档与恢复的语义
- 如何通过任务中心统一跟踪训练相关任务

## 7.2 前置条件

- 已进入目标项目，参见 [SOP-1 项目管理](01-project.md)。
- 数据集已准备就绪，标签基本可用，参见 [SOP-3 数据标注](03-annotation.md)。
- 当前设备资源足够（参见 §7.6）。
- 已选定基线模型（预训练模型或历史模型）。

## 7.3 工作流是什么

工作流是同一个数据集上"多次训练尝试 + 评估 + 导出 + 部署模板"的统一容器：

- 一个工作流只属于一个项目 + 一个数据集。
- 工作流下聚合多条任务记录（训练 / 评估 / 导出 / 部署模板）。
- 工作流可被归档，归档后不再作为当前迭代的工作区，但历史任务与产物仍可访问。

## 7.4 业务动作

### 创建工作流

当前项目 + 数据集存在、且未归档工作流数小于配置上限时，就可以创建。工作流元数据落盘后，具体任务按各自动作落点继续写。

### 训练配置

选择模型 + 训练参数，作为一次训练任务的输入。**配置会随训练任务一起快照保存**（参见 §7.7），后续即使配置被改了，也能复现当时那次训练。

### 启动训练

准备工作流 + 配置 + 资源之后启动一次训练任务，结果落在 §7.7 的目录树里。

### 任务详情

观察训练进度、日志摘要、当前指标、是否可继续训练。该视图**只读取已有任务记录**，不会产生新的写盘。

### 测试评估

在 `test` split 上评估当前最佳权重。评估结果随训练任务一起持久化。**数据集存在 `test` split 才可以发起评估**，否则该入口受限。

### 模型导出

把当前权重导出为部署格式（ONNX / OpenVINO / TensorRT / 留作 PT 源）。导出产物落在工作流任务目录下，可以下载、可以删除。

### 部署模板生成

基于源模型生成可运行的部署模板包（FastAPI / Python SDK / 批处理），落在工作流任务目录下，可以下载、可以删除。**模板是独立任务，与模型导出完全解耦**：

| 源类型 | 是否可作为模板源 | 模板与导出关系 |
| --- | --- | --- |
| `pt`（最佳 / 最后权重） | 是 | 不依赖导出产物 |
| 已导出 `onnx` / `openvino` / `engine` | 是 | 模板任务独立，不复用导出产物 |

> 模板任务的执行模式与训练 / 导出完全一致——任务表驱动 + 轮询进度，不引入独立的实时通道。

### 归档 / 恢复工作流

**归档**：把工作流标记为 `archived`，不再作为当前迭代入口；其下任务与产物保留。**恢复**：清除 `archived` 标记，重新出现在"当前工作流"入口。

### 删除工作流

硬删除该工作流下所有任务记录与产物目录。**系统会要求二次确认**，已下载的产物文件不会被这次删除带走，但未备份的就找不回来了。

## 7.5 模型怎么选

| 来源 | 推荐场景 |
| --- | --- |
| 预训练模型 | 第一次训练一个数据集时优先 |
| 同项目历史模型 | 同数据集持续迭代 |
| 同任务类型模型 | 跨项目复用，如 `-pose` 系列训练同任务 |

> 训练前必须确认模型文件名后缀对应的任务类型与数据集一致，例如 `-pose` 模型只能用于 `pose` 数据集。

## 7.6 环境与批次校准

### 环境画像

来自当前主机的设备信息（CPU / 内存 / GPU）的**只读快照**，为训练参数与校准提供基线，不会自动改写训练配置。

### 批次校准

第一次在这台机器上训练 / 换了模型 / 改了图片尺寸 / 不确定当前环境能承受多大的批次时发起。结果随训练任务持久化，**校准结果是参考，不会自动改写训练配置**。

## 7.7 训练产物

```text
projects/<project>/training_outputs/<dataset_name>/<run_id>/
├── config_snapshot.json          # 训练配置快照
├── metrics/                       # 评估指标与历史
├── weights/
│   ├── best.pt
│   └── last.pt
├── export/<export_task_id>/       # 导出产物
└── template/<template_task_id>/  # 部署模板产物
```

## 7.8 任务状态与失败排查

### 状态机

| 状态 | 语义 |
| --- | --- |
| `pending` | 等待调度 |
| `running` | 正在执行 |
| `completed` | 执行成功 |
| `failed` | 执行失败，附带错误信息 |
| `cancelled` | 被取消 |
| `stopped` | 被主动停止，可恢复 |

### 任务中心

跨工作流、跨任务的统一回看入口，可以按项目 / 任务类型 / 状态过滤。任务中心**只读取，不写盘**。

### 失败排查

| 现象 | 排查方向 |
| --- | --- |
| 训练启动即失败 | 检查数据集结构、模型可用性、参数范围 |
| 显存 / 内存不足 | 减小批次或降低图片尺寸 |
| 训练很慢 | 用更小图片尺寸与保守参数验证流程 |
| 模板生成一直 0% | 确认任务是否进入任务中心；如果已下发但仍停滞，检查 worker 是否注册了对应任务类型 |
| 模板进度看不到更新 | 模板任务遵循与训练 / 导出相同的轮询机制；进入页面时如果有 active 任务会自动恢复轮询 |

## 7.9 视觉任务类型与训练模式

| 任务类型 | 训练模式 | 模型后缀约定 |
| --- | --- | --- |
| `detect` | `yolo_detect` | `*-yolo*.pt` |
| `classify` | `yolo_classify` | `*-cls*.pt` |
| `segment` | `yolo_segment` | `*-seg*.pt` |
| `pose` | `yolo_pose` | `*-pose*.pt` |

# 按钮职责与颜色规范

## 目标

本规范用于收口 Vision Train 前端中的按钮颜色、权重和使用场景，解决以下问题：

- 主蓝色使用范围过大，页面中“重点”过多
- 深色实心次按钮视觉权重过重，容易和主按钮争抢层级
- 同类动作在不同页面使用了不同按钮语言
- 局部区域缺少“唯一主操作”的明确表达

本规范优先服务于当前项目的工具型界面，强调：

- 品牌主色明确
- 操作层级稳定
- 颜色语义单一
- 在复杂工作流界面中保持克制

## 当前判断

### 现状结论

- 当前主蓝色本身没有问题，适合作为品牌主操作色
- 当前深色实心次按钮不够理想，因为它视觉权重过高，容易形成“第二个主按钮”
- 当前最大问题不是单个颜色不好看，而是主蓝承担的语义过多

### 当前主要问题

主蓝色目前同时被用于：

- 主操作按钮
- 选中态
- step 激活态
- badge / 小标签
- 进度条
- checkbox / radio
- 局部推荐态和提示态

这会导致：

- 页面同时出现太多“重点”
- 主按钮不再足够突出
- 结构层、状态层、动作层都在争夺同一个颜色

## 总体原则

### 原则一：一个区域只有一个主 CTA

在一个局部区域内，原则上只允许出现一个蓝色实心主按钮。

例如：

- 弹窗底部只保留一个蓝色确认按钮
- 训练表单区域只保留一个蓝色“开始训练”
- 数据集操作条只保留一个当前最关键的蓝色动作

### 原则二：次按钮不再使用深色实心

深色实心按钮不应作为常规次按钮使用。

原因：

- 它和主按钮一样重
- 它更像结构色，不像次操作色
- 会让页面同时出现两个“很强”的视觉中心

次按钮应统一降级为：

- 白底描边
- 浅灰底
- ghost
- link

### 原则三：颜色只表达一种语义

每种颜色在交互层面只承担少数固定职责，不允许一个颜色同时表达多层语义。

例如：

- 蓝色负责“主操作 / 当前选中 / 品牌激活”
- 红色只负责危险行为
- 灰色负责中性动作和结构辅助

### 原则四：状态色弱于动作色

进度条、badge、选中卡片、tab 激活等状态表达，虽然可以继续用蓝系，但不能和主按钮使用同等权重的蓝色。

应优先使用：

- 浅蓝底 + 蓝边
- 柔和蓝文字
- 低饱和蓝条

而不是继续复用主按钮蓝底白字。

## 颜色角色定义

### 1. 主操作色

- 角色：`Primary Action`
- 建议 token：`--vt-color-primary`
- 当前色值：`#2563eb`
- 使用范围：
  - 开始训练
  - 创建
  - 开始生成
  - 导出确认
  - 当前弹窗中的最终确认动作

规则：

- 仅用于当前区域唯一主 CTA
- 不用于普通跳转、过滤、开关、查看详情
- 不用于结构元素和说明性状态

### 2. 中性次按钮色

- 角色：`Secondary Action`
- 建议视觉：白底描边或浅灰底
- 主要承担：
  - 取消
  - 返回
  - 预览
  - 查看
  - 次要打开操作
  - 不改变主流程结果的辅助动作

建议：

- 用灰 / slate 系表达
- 不再使用深色实心作为默认次按钮

### 3. 危险色

- 角色：`Danger Action`
- 建议 token：`--vt-color-danger`
- 当前色值：`#e11d48`
- 使用范围：
  - 删除
  - 永久删除
  - 清空
  - 不可逆确认

规则：

- 只用于危险动作
- 不可用于普通强调
- 不可与蓝色主 CTA 同时抢占同一视觉层级

### 4. 结构辅助色

- 角色：`Neutral / Structural`
- 使用范围：
  - icon-only 按钮
  - 文本按钮
  - 面包屑辅助交互
  - 非主要分页按钮
  - 展开/收起
  - 工具栏小操作

规则：

- 优先用 slate / gray 体系
- hover 可以加深，但不变成主蓝

### 5. 选中与激活色

- 角色：`Selected / Active State`
- 表达方式：
  - 浅蓝底
  - 蓝边
  - 蓝字
- 使用范围：
  - 列表选中
  - tab 激活
  - chip 选中
  - 可选卡片选中
  - checkbox / radio / switch 的选中反馈

规则：

- 使用蓝系，但权重必须低于主按钮
- 不应出现大面积蓝底白字卡片，除非它本身是主操作按钮

## 按钮职责映射

### 必须使用主蓝实心的场景

- 当前面板唯一最终确认动作
- 当前流程的开始动作
- 需要推动用户进入下一步的关键动作

典型文案：

- 开始训练
- 开始生成
- 创建
- 导出
- 确认

### 应使用中性次按钮的场景

- 取消
- 返回
- 预览
- 先估算
- 查看详情
- 导入但不是当前唯一主流程
- 打开设置

### 应使用文字按钮或图标按钮的场景

- 翻页
- 展开 / 收起
- 三点菜单
- 面包屑
- 轻量跳转
- 关闭弹窗
- 卡片右上角工具操作

### 应使用危险按钮的场景

- 删除数据集
- 永久删除工作流
- 清空记录
- 删除导出记录

## 当前项目的具体收口建议

### 建议一：移除“深色实心次按钮”作为通用按钮

建议把当前 `vt-btn-solid-secondary` 的职责收窄：

- 不再作为通用二级操作按钮
- 如果保留，只保留给极少数结构级入口

更推荐的调整方式：

- 默认二级按钮使用 `vt-btn-secondary`
- 需要更弱时使用 `vt-btn-muted`
- 极轻动作使用 `vt-btn-link` 或 `vt-icon-btn`

### 建议二：限制蓝色实心按钮数量

页面 / 面板 / 弹窗内应遵守：

- 每个局部区域最多一个蓝色实心主按钮
- 如果已有主按钮，其他操作必须降级

示例：

- 训练页右下“开始训练”为主按钮时，右侧说明区中的“开始”不应继续是同等强度蓝按钮
- 弹窗中已有“创建”，则“取消”必须是中性按钮

### 建议三：把状态层的蓝和动作层的蓝拆开

建议保留一个主蓝 token，同时建立更轻的状态表达：

- `primary`: 主按钮蓝
- `primary-soft-bg`: 浅蓝底
- `primary-soft-border`: 浅蓝边
- `primary-soft-text`: 较柔和蓝字

这样可用于：

- 选中卡片
- 当前步骤
- 信息 badge
- 推荐标签
- 进度条

而不是继续复用主按钮蓝。

### 建议四：统一按钮优先级

建议固定以下优先级：

1. 主按钮：蓝色实心
2. 次按钮：白底描边 / 浅灰底
3. 弱按钮：文字 / icon
4. 危险按钮：红色，仅用于危险动作

不要再出现：

- 深色实心次按钮和蓝色主按钮并列
- 同一区域多个蓝色实心按钮并列
- 用红色做普通强调

## 推荐的组件协议

### 保留

- `vt-btn-solid-primary`
- `vt-btn-secondary`
- `vt-btn-muted`
- `vt-btn-link`
- `vt-icon-btn`
- `vt-btn-danger`
- `vt-btn-solid-danger`

### 收窄或重构

- `vt-btn-solid-secondary`

建议：

- 逐步退出通用场景
- 后续仅在确认有必要时保留给极少数结构级操作

## 反例

以下情况应视为不符合规范：

- 一个弹窗底部同时出现两个实心高权重按钮
- 一个面板内多个蓝色按钮并列，且都像主按钮
- 选中态卡片使用与主按钮完全相同的蓝底白字
- badge、步骤条、推荐标签都使用主按钮同色同权重蓝
- 普通“返回 / 预览 / 查看”使用主按钮色

## 实施顺序

建议按以下顺序收口：

1. 先收按钮职责，不先换色值
2. 把 `vt-btn-solid-secondary` 从通用场景撤掉
3. 把页面级“多个蓝色实心按钮并列”问题先清掉
4. 再把选中态、badge、progress 拆到浅蓝状态层
5. 最后再微调蓝色和灰色的具体色值

## 最终结论

当前主蓝色可以保留，不需要更换。

真正需要调整的是：

- 主蓝色的使用边界
- 次按钮的视觉权重
- 状态层和动作层对蓝色的复用方式

最终目标不是“颜色更少”，而是：

- 让主按钮重新成为真正的主按钮
- 让次按钮回到次按钮的位置
- 让选中态和信息态不再冒充主动作
